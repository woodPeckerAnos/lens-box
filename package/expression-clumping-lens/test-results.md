# 表达成团透镜的测试结果

## 一个玩笑怎样隔了几晚又被接起来

这个例子保留了两人聊汉堡时用过的“开窍”，店铺、地点和对白均已改写。次数来自八晚的合成材料。

第一晚，楼下那家店换了面包，肉饼终于不会一咬就滑出来。一个人说：“是啊，他们可算开窍了。”隔了两天，听说要去河边吃汉堡，对方想起了楼下那家。他接着解释：“楼下那家是开窍了。这家我可没舍得点外卖，想带你去吃刚出炉的。”

| 表达 | 总次数 | 覆盖夜数 |             成团分数 |
| ---- | -----: | -------: | -------------------: |
| 晚安 |      8 |        8 |                0.000 |
| 门口 |      3 |        3 |               -0.405 |
| 开窍 |      3 |        2 |                0.000 |
| 枕头 |      1 |        1 | 无分数，出现不足三次 |
| 月票 |      0 |        0 |       无分数，未出现 |

“开窍”第一晚出现一次，第三晚出现两次。这个频档校准后预期覆盖两晚，所以它的分数恰好是零。“门口”分散在三晚，得分为 `ln(2/3) ≈ −0.405`。这个回勾很自然，却没有得到高分。单靠一个正分门槛就会漏掉它。

## 为什么互道晚安也会显得集中

另写十六段睡前闲聊，开头相同，八段用日语收尾，八段用中文收尾。用日语的八晚，两个人各说一声“おやすみ”。两次计算中，这十六声晚安都原样保留。

| 参照语料   | 总夜数 | 出现次数 | 覆盖夜数 | 校准期望夜数 | 成团分数 |
| ---------- | -----: | -------: | -------: | -----------: | -------: |
| 全部夜聊   |     16 |       16 |        8 |           16 |    0.693 |
| 仅日语收尾 |      8 |       16 |        8 |            8 |    0.000 |

混合语料里的“おやすみ”得分比“开窍”更高。回看对白，“おやすみ”的集中可以用道晚安时选了哪种语言解释；“开窍”则确实接上了先前的玩笑。

## 复现

以上正文由确定性的合成生成器直接构造，可以公开逐行核算。[两组夜聊全文](./demo/synthetic-corpus.ts) · [可执行断言](./test/clumping.test.ts)

在 lens-box 根目录运行。验证环境为 Node.js 26.3.0、pnpm 9.5.0，上游版本 `dbee564`。

```sh
pnpm install --frozen-lockfile
pnpm --filter @lsby/lens-box-expression-clumping-lens test
pnpm --filter @lsby/lens-box-expression-clumping-lens demo
pnpm check
```

本轮运行通过 10/10 项测试。工作区的格式检查、ESLint、类型检查及全量构建均通过。十项测试覆盖同频表达的手算值、负分、逐篇计数、缺少参照、上下档等距、上中位数、Unicode 重叠与边界、固定种子复算及非法输入。`demo` 逐行输出这两张表对应的完整 JSON。

## 原应用的公开汇总

Hikaru 另有一次按天切分的历史回放，共 30 个有记录的日子、1,891 条发言。在原有入口规则上增加“一般语言中常见、本地分布较散、出现超过六次”这个联合条件后，会递送旧材料的发言从 100 条降到 64 条。64 条中 34 条被判有用。新规则移除的 37 条中，旧报告估计约有 4～5 条原本有用。该回放在同一份材料上探索参数，其结果用于说明联想入口的实际取舍。新 TypeScript 包的验证使用上面两组合成材料。[原报告与统计口径](https://github.com/ikarugaikoi/hikaru-memory/blob/main/docs/limitations.md)
